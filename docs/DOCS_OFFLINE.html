    🚀 Getting Started

    Installation, prerequisites, and quick-start guide

    This section covers everything you need to install and configure before running the fMRI Preprocessing pipeline.

    1

    Download Python 3.9+

    The pipeline requires Python 3.9 or newer. Check your version:

    python --version
# or
python3 --version

    If you need to install Python, download it from python.org or use your system package manager.

    macOS (Homebrew) 
    brew install python@3.11
    Ubuntu / Debian 
    sudo apt update && sudo apt install python3 python3-pip python3-venv
    Windows

    Download the installer from python.org. During installation, check "Add Python to PATH".

    2

    Python Packages

    Tip: If you skip this step, run.py will automatically detect and install missing packages on first launch.

    Install required packages using the provided requirements file:

    cd /path/to/project
python -m venv venv
source venv/bin/activate    # macOS/Linux
# venv\Scripts\activate     # Windows
pip install -r requirements.txt
    3

    Docker Desktop

    Both MRIQC and fMRIPrep run inside Docker containers. Install Docker Desktop from docker.com.

    Tip: The pipeline automatically checks whether Docker is running and will attempt to start it for you. If it cannot start Docker automatically, you will be notified so you can open Docker manually.

    Recommended Resource Settings

    Open Docker Desktop → Settings → Resources to adjust these values.

    ResourceMinimumRecommendedNotes
    CPU Cores48+More cores = faster parallel processing
    RAM8 GB16+ GBfMRIPrep is memory-intensive
    Disk Space30 GB50+ GBDocker images + intermediate files
    4

    dcm2niix (Bundled)

    The DICOM-to-NIfTI converter dcm2niix is already bundled in the tools/ directory. No additional installation is needed. If you prefer to use your own installation, the pipeline will find dcm2niix on your system PATH as a fallback.

    5

    FreeSurfer License (Optional)

    A license file is already included at tools/.freesurfer_license.txt and should not expire. No action is needed unless you encounter a license error.

    This is only needed if you enable FreeSurfer surface reconstruction in the pipeline options. If the bundled license has expired or you need your own:

    1. Register at surfer.nmr.mgh.harvard.edu (free, takes ~2 minutes)
    2. You'll receive a license.txt file by email
    3. Place it in the tools/ folder as .freesurfer_license.txt

    2

    Researcher Comments

    A free-text field for documenting contextual information that cannot be inferred from the imaging data alone. This is the appropriate place to record behavioural observations, participant-reported events (e.g., drowsiness, task confusion, discomfort), scanner incidents (e.g., early termination, coil repositioning), protocol deviations, or any other circumstances that may account for irregularities in the data.

    Comments can be edited at any point while the pipeline is running. Each report captures the text as it exists at the time that report is generated, so entries may be updated or refined between pipeline stages. Once processing completes, the comment field is no longer editable. The saved comments are embedded in every HTML report produced during the session.

    3

    fMRIPrep Options

    The collapsible fMRIPrep Options panel in the GUI lets you customize how fMRIPrep processes your data. Default settings work well for most studies - only change them if you have a specific reason.

    Output Spaces

    At least one output space must be selected. These control the coordinate system of your preprocessed images:

    CheckboxDefaultWhat It DoesWhen to Change
    MNI152NLin2009cAsym @ 2mm
    (standard brain template)    		 ON Warps each subject’s brain into a standard template space (MNI). Required for group-level analyses. Leave on for nearly all studies.
    Native T1w space
    (subject’s own brain)    		 OFF Outputs data aligned to the subject’s own T1w image, without normalization. Turn on for subject-specific ROI or surface-based analyses.
    Important: At least one output space must be selected. The GUI will show a validation warning if both are deselected.

    Processing Options

    CheckboxDefaultWhat It DoesWhen to Change
    Slice timing correction ON Corrects for different slice acquisition times within each TR. Turn off if TR is very short (<1s) or your analysis accounts for slice timing.
    FreeSurfer surface reconstruction
    (adds approx. 6h per subject)    		 OFF Reconstructs cortical surfaces for surface-based analyses. Turn on if you need cortical thickness or fsaverage projections.
    Fieldmap-less distortion correction
    (SyN SDC)    		 OFF Estimates and corrects EPI distortion without fieldmap data. Turn on if you have no fieldmaps and see visible distortion.
    Anonymize DICOM metadata
    (remove patient info)    		 OFF Strips identifying information from DICOM headers during conversion. Turn on if sharing data publicly.
    Tip: If unsure, leave the defaults. MNI space + slice timing correction works for the vast majority of task-based fMRI studies.
    4

    Quality Check Thresholds

    The collapsible Quality Check Thresholds panel lets you adjust the Warning and Error thresholds used across all QC layers before launching a run. All thresholds are editable and the values you set will be used when generating the QC reports.

    The panel contains four cards - MRIQC Anatomical, MRIQC BOLD, Motion Analysis, and Connectivity Quality Check - each showing its metrics with editable Warning and Error value fields pre-filled with defaults. Values are validated live - non-numeric input is highlighted in red and blocks the Save button.

    • Save - Confirms your threshold overrides for the current session. Only enabled when at least one value differs from the saved state and all values are valid.
    • Reset to Defaults - Reverts all fields to the original default values.
    5

    Workflows

    Each button corresponds to a different pipeline workflow. Buttons remain disabled until the required folder structure is detected; while disabled, the expected input is shown beneath each button. Once enabled, an estimated processing duration is displayed instead.

    Full Pipeline Most Common

    Run everything: BIDS conversion, MRIQC, fMRIPrep, motion analysis, and final report. This is the default workflow for new datasets. Select your input and output folders, then click Full Pipeline.

    BIDS Only

    Convert DICOM data to BIDS format without running any further processing. Useful for validating the conversion output before committing to downstream analyses.

    BIDS + MRIQC Only

    Convert to BIDS and run image quality assessment. Use this for a quick quality check before committing to the full pipeline. Click BIDS + MRIQC in the GUI. You can run fMRIPrep later on the same output folder.

    fMRIPrep Only

    If you already have data in BIDS format. Click fMRIPrep Only. Skips BIDS conversion entirely.

    Connectivity QC Only

    Re-run quality analysis on an existing output folder without re-processing. Click Connectivity QC Only. Useful after updating thresholds or when you want a fresh report.

    6

    Execution Logs

    The log panel displays live, color-coded output as the pipeline runs. This is the primary place to monitor progress and diagnose issues - if a step fails, the error message and context will appear here immediately.

    All console output is mirrored to disk in real time at <output_folder>/execution_logs/raw_execution_log.log. When the run completes, a structured summary is also written to execution_logs/execution_logs_summary.txt. A separate execution_report.txt in the output root provides a plain-text overview of the run including BIDS conversion results, scan counts, and next-step guidance. All files are available for review even if the GUI is closed, and can be shared when reporting issues.

    File Types Explained

    .nii.gz

    NIfTI (compressed)

    The standard neuroimaging format. Contains 3D (structural) or 4D (functional time series) brain volumes. Open with FSLeyes, FreeSurfer, or any NIfTI viewer.

    .json

    JSON Sidecar

    Machine-readable metadata accompanying each NIfTI file. Contains scan parameters (TR, TE, flip angle, etc.) and processing provenance.

    _confounds_timeseries.tsv

    Confound Regressors

    Tab-separated table from fMRIPrep with one row per volume. Columns include framewise displacement, motion parameters, CompCor components, and more. Essential for first-level analysis.

    .tsv

    Tab-Separated Values

    Used for participant lists, group metrics, and events files. Open in any spreadsheet application or load with pandas.

    .html

    Visual Reports

    Self-contained HTML reports with embedded images. Open directly in any web browser. No server or internet required.

    .npy

    NumPy Array

    Binary format for connectivity matrices (when connectivity quality check is enabled). Load with numpy.load().

    📄 Reports

    Understanding the pipeline reports - section by section

    The pipeline produces two reports:

    1. full_pipeline_report.html - The primary output, aggregating all quality check findings from every pipeline phase into a single document.
    2. mriqc_report.html - Standalone report generated as soon as MRIQC completes, before fMRIPrep starts. Contains the same Scan Quality and MRIQC sections as the full report, allowing early quality check review.

    Both are self-contained HTML files written to the output folder root. The sections below walk through the full pipeline report in detail.

    Full Pipeline Report

    full_pipeline_report.html - open in any browser. The file is fully self-contained (no internet required). It is divided into the following sections, presented in order.

    2. Scan Quality

    Checks performed immediately after DICOM-to-BIDS conversion, before any preprocessing begins. The report flags:

    • Missing scans - expected sequences (T1w, BOLD) not found
    • Truncated runs - files with suspiciously few volumes
    • Duplicate or fragment runs - split artifacts from dcm2niix, with the shorter fragment automatically excluded
    • Parameter drift - TR or field strength inconsistencies across sessions

    Each issue is listed with the subject/session, a category label, and a plain-language explanation of what was detected and what the pipeline did about it.

    3. MRIQC - Image Quality Metrics

    A table of quantitative image quality metrics, separated into structural (T1w) and functional (BOLD) rows. Each metric value is color-coded:

    Normal Borderline Out of range

    Structural metrics: SNR (signal-to-noise), CNR (contrast-to-noise), CJV (tissue overlap), INU range (bias field), QI1 (background artifacts).

    Functional metrics: tSNR (temporal stability), FD mean (head motion), GSR X/Y (ghosting), AOR (outlier ratio).

    Note on FD mean: The FD reported here is computed by MRIQC on the raw, unprocessed BOLD data - it reflects head motion as it existed before any correction. The Motion Analysis section (below) reports a separate FD derived from fMRIPrep's confounds files after realignment and preprocessing. The two values may differ slightly; MRIQC's FD is a measure of raw data quality, while fMRIPrep's FD reflects residual motion in the preprocessed output.

    Metrics are evaluated on three layers:

    1. Absolute safety-net thresholds - protocol-independent ERROR thresholds that catch extreme values regardless of dataset size (e.g., tSNR < 5, FD > 1.0 mm). Always applied, even for single scans.
    2. Within-study comparison - when 3 or more scans of the same modality are available, the pipeline performs IQR-based outlier detection (Tukey’s fences) across the dataset:
      • For metrics where higher is worse: flags values above Q3 + 1.5 × IQR
      • For metrics where lower is worse: flags values below Q1 − 1.5 × IQR
      • A metric beyond 1.5× IQR is marked Borderline
      • Beyond 3× IQR is marked Out of range
      This helps you spot scans that deviate from the rest of your dataset even if they pass absolute thresholds.
    3. Fallback warning thresholds - when fewer than 3 scans are available and IQR detection cannot run, the pipeline falls back to absolute WARNING thresholds for each metric. These are less sensitive than within-study comparison but ensure every scan receives at least a basic quality check.

    For BOLD rows, a carpet plot is available behind a collapsible toggle. See Reading Carpet Plots below for interpretation guidance.

    Reading Carpet Plots

    Carpet plots (also called grayplots) appear behind a collapsible toggle on each BOLD row. They provide a single-image summary of the entire functional run.

    • Rows = brain voxels, grouped by tissue type (gray matter, white matter, CSF)
    • Columns = time points (one per TR / volume)
    • Color = normalised signal intensity
    • Traces above the plot = framewise displacement (FD) and DVARS

    What to Look For

    PatternWhat It MeansAction
    Smooth horizontal bands, no vertical stripes ✓ Clean data No action needed
    Vertical stripes (bright or dark columns) Warning Whole-brain signal shift - usually head motion Check FD trace; motion scrubbing may salvage the data
    Large blocks of vertical stripes Error Sustained motion period Consider excluding the run if >20% is affected
    Slow vertical drift ✓ Scanner drift Normal; high-pass filtering handles this
    Bright/dark bands in CSF rows ✓ CSF pulsation Normal; confound regression handles this
    Global intensity shift (sudden brightness change) Warning Scanner spike or repositioning Check if fMRIPrep recovered; may need exclusion

    5. fMRIPrep Registration Quality

    Coregistration overlays showing each BOLD run's reference volume superimposed on the subject's T1-weighted anatomical scan. Grouped by subject/session and collapsed by default - click to expand.

    The BOLD outline (red/warm contour) should closely trace the cortical surface boundaries visible in the T1w (grayscale). If you see a clear shift, rotation, or warping between the two, that run's alignment failed and the data should be reviewed. See Reading Coregistration Plots below for a detailed guide.

    Why only coregistration? Of all fMRIPrep diagnostic figures, this is the one that directly answers: "Did preprocessing produce a usable spatial alignment?" Failed coregistration invalidates all downstream analyses, yet it is not captured by any numerical metric. Other fMRIPrep figures (carpet plots, confound matrices, segmentation overlays) remain available in derivatives/sub-<ID>.html.

    Reading Coregistration Plots

    The coregistration overlays show the BOLD reference aligned onto the T1w anatomical. This is the single most important visual check for preprocessing accuracy.

    • Background = T1-weighted anatomical (grayscale) showing gyri, sulci, and ventricles
    • Overlay = BOLD reference image (red/warm contour lines)
    • Goal = the BOLD outlines should trace the cortical surface boundaries visible in the T1w

    What to Look For

    PatternWhat It MeansAction
    BOLD outlines follow cortical boundaries closely ✓ Good coregistration No action needed
    Slight offset (<1-2 voxels) in one direction Warning Minor misalignment Note it; likely still usable for standard analyses
    Clear shift or rotation between BOLD and T1w Error Failed coregistration Check if the run had excessive motion; exclude from analysis
    BOLD edges appear warped or stretched Error Geometric distortion Consider enabling fieldmap-less distortion correction (SyN SDC)
    Signal dropout in frontal/temporal BOLD regions Warning Susceptibility-related signal loss Common near sinuses/ear canals; check overlap with your ROIs

    6. Functional Connectivity Quality Assessment

    Evaluates whether each BOLD run has sufficient data quality for functional connectivity analysis. Connectivity estimates are especially sensitive to head motion - even small movements can introduce spurious correlations and distort network structure. This section uses Nilearn’s scrubbing strategy to censor high-motion volumes, then computes connectivity matrices on the cleaned data. Thresholds follow Wang et al., 2024.

    Quality Metrics

    A table showing connectivity-specific metrics for each BOLD run:

    • Mean FD - average framewise displacement. < 0.25 mm OK, 0.25-0.50 mm caution, > 0.50 mm unsuitable.
    • Censored - percentage of volumes flagged by the scrubbing strategy and removed before time-series extraction. > 80% = not suitable.
    • Usable Time - clean scan duration remaining after censoring (in minutes). < 1 min = not suitable.
    • # Regressors - number of confound columns selected by the scrubbing strategy.
    • Loss of DoF - total temporal degrees of freedom consumed by regressors + censored volumes. High values reduce statistical power. > 60% = caution.

    🔍 MRIQC

    Visual guide to every MRIQC figure - what it shows and how to read it

    MRIQC generates several diagnostic figures for each scan. These figures help you spot problems with image quality before investing hours in preprocessing. This page walks you through each figure type with real examples from the pipeline output.

    Note: MRIQC produces separate figures for structural (T1-weighted) and functional (BOLD) scans. Both types are covered below.

    Shared Figures - T1w & BOLD

    MRIQC produces a Background Mosaic and a Zoomed Brain figure for both structural (T1w) and functional (BOLD) scans. The visual layout is the same, but what you should look for differs between modalities.

    Background Mosaic

    T1w: sub-*_desc-background_T1w.svg  |  BOLD: sub-*_task-*_desc-background_bold.svg

    What This Shows

    A mosaic of axial slices displayed at a wide intensity window. The background (air around the head) is highlighted to reveal noise, ghosting, or wrap-around artifacts. Each small panel is one slice; together they cover the brain from bottom to top. MRIQC generates this figure for both the T1-weighted anatomical scan and the mean BOLD image.

    What to Look For

    T1w

    Focus on the area outside the skull. A healthy scan shows almost pure black background. If you see a faint “ghost” of the brain floating in the air region, this indicates Nyquist ghosting - the scan may still be usable, but check the quantitative metrics (SNR, FBER) for confirmation.

    ✓ Good Signs
    • Clean, uniform dark background
    • No bright rings or streaks outside the head
    • Clear brain-to-background boundary
    ✗ Problems
    • Ghosting (faint copy of the brain outside the head)
    • Wrap-around artifact (brain overlapping from opposite side)
    • High background noise (bright speckles everywhere)

    BOLD

    EPI scans are particularly susceptible to Nyquist ghosting - look for a faint, shifted copy of the brain in the background. Some signal dropout in the orbitofrontal cortex and medial temporal lobes is normal for EPI sequences; complete signal loss in these areas may limit your ability to study those regions.

    ✓ Good Signs
    • Clean background with minimal noise
    • No ghost images visible outside the head
    • Brain shape looks complete (no major dropout)
    ✗ Problems
    • Ghosting (faint copy shifted in phase-encode direction)
    • Signal pileup at air-tissue boundaries
    • Large black holes in orbitofrontal or temporal regions

    Zoomed Brain

    T1w: sub-*_desc-zoomed_T1w.svg  |  BOLD: sub-*_task-*_desc-zoomed_bold.svg

    What This Shows

    The same volume cropped tightly to the brain and displayed with an intensity window optimized for tissue contrast. This view helps you evaluate tissue quality and whether artifacts have degraded anatomical detail. MRIQC generates it for both the T1-weighted scan and the mean BOLD image.

    What to Look For

    T1w

    Look at the interface between grey and white matter - it should appear as a crisp line. If the entire image looks “soft” or blurry, the subject likely moved during acquisition. Intensity gradients across the image (e.g., one hemisphere brighter than the other) indicate bias-field issues which fMRIPrep can usually correct, but severe cases affect segmentation.

    ✓ Good Signs
    • Sharp edges between grey and white matter
    • Clear cortical folding visible
    • Consistent intensity across the brain
    ✗ Problems
    • Blurry boundaries between tissues (motion blur)
    • Bright/dark intensity bands (B1 inhomogeneity)
    • Ringing artifacts (parallel lines near bright edges)

    BOLD

    Compare the overall brain shape to what you expect from an axial view. Geometric distortions from susceptibility effects typically appear as stretching or compression near air-tissue boundaries (sinuses, ear canals). Mild distortion is normal for EPI; severe distortion may indicate problems with shimming.

    ✓ Good Signs
    • Brain structures recognizable despite lower resolution
    • Relatively uniform signal across the brain
    • No geometric distortion (brain not warped)
    ✗ Problems
    • Severe geometric distortion (brain looks stretched or compressed)
    • Large signal voids (black holes in the image)
    • Very blurry or smeared appearance

    BOLD-Only Figures

    The following figures are generated only for functional (BOLD) scans, as they assess temporal properties or EPI-specific characteristics that do not apply to single-volume structural scans.

    Standard Deviation Map

    sub-*_ses-*_task-*_desc-stdev_bold.svg

    What This Shows

    A map of voxel-wise standard deviation across the entire BOLD time series. Brighter voxels had more signal variability over time. In a well-behaved scan, the highest variability should be in grey matter (where neural activity causes signal changes) and around blood vessels and the brain edges.

    What to Look For

    A bright “halo” around the edge of the brain is the classic sign of head motion - as the head moves, the boundary between brain and non-brain tissue shifts, creating high temporal variability at the edge. Mild halos are common and tolerable; thick, bright halos suggest excessive motion.

    ✓ Good Signs
    • Highest variability in cortical grey matter
    • Low variability in white matter and CSF
    • Symmetric pattern between hemispheres
    ✗ Problems
    • Bright ring at the brain edge (motion artifact)
    • Uniformly high variability everywhere (global noise)
    • Bright bands or stripes (scanner artifact)

    Carpet Plot (BOLD)

    sub-*_ses-*_task-*_desc-carpet_bold.svg

    What This Shows

    A "carpet plot" (also called a grayplot) displays every voxel in the brain as a row, with time running along the horizontal axis. The intensity represents signal changes over time. The rows are grouped by tissue type (cortical grey matter, subcortical grey matter, white matter, CSF). Above the carpet, you may see a framewise displacement (FD) trace showing head motion at each time point.

    What to Look For

    Vertical stripes that span all voxels simultaneously are the hallmark of motion artifacts -they indicate frames where the entire brain shifted. A few isolated stripes are tolerable (these frames can be censored during analysis), but if the carpet is dominated by stripes, the run may be unusable. Also look for slow drift patterns (gradual color shifts from left to right), which indicate scanner drift.

    ✓ Good Signs
    • Relatively uniform "texture" across time
    • No prominent vertical stripes
    • FD trace stays low and flat
    ✗ Problems
    • Bold vertical stripes (=global signal spikes from motion)
    • Wide bright/dark bands spanning all voxels
    • FD trace with tall spikes (>0.5 mm)

    Mean Signal Map

    sub-*_ses-*_task-*_desc-mean_bold.svg

    What This Shows

    The temporal mean of the BOLD signal across all time points, displayed as a mosaic. This gives you a "summary" view of the average signal intensity at each voxel, useful for identifying areas of consistent signal loss or unusual intensity patterns.

    What to Look For

    Verify that the brain coverage includes all regions you intend to analyze. Signal dropout in the orbitofrontal cortex and inferior temporal lobes is common with standard EPI sequences. If your study targets these regions, consider whether the dropout extent is acceptable or if specialized acquisition parameters are needed.

    ✓ Good Signs
    • Even signal intensity across the brain
    • Good brain coverage (all expected regions visible)
    • Clear brain boundaries
    ✗ Problems
    • Large dark regions (signal dropout)
    • Strong intensity gradient across the image
    • Incomplete brain coverage (top or bottom cut off)

    🧠 fMRIPrep

    Visual guide to fMRIPrep quality check figures - registration, segmentation, and carpet plots

    fMRIPrep generates quality-control figures at each processing step. These figures let you verify that automatic processing worked correctly for each subject. Reviewing them is essential before trusting the preprocessed data for statistical analysis.

    Note: fMRIPrep figures differ from MRIQC figures. While MRIQC evaluates raw image quality, fMRIPrep figures verify that each processing step (segmentation, registration, denoising) succeeded.

    Anatomical Figures

    These figures show how fMRIPrep processed the high-resolution T1-weighted scan: tissue segmentation and spatial normalization to a standard brain template.

    Brain Segmentation

    sub-*_dseg.svg

    What This Shows

    The T1-weighted brain image with colored overlays showing the tissue classification: grey matter (GM), white matter (WM), and cerebrospinal fluid (CSF). Each tissue class is shown in a different color. The segmentation is critical because it drives many downstream steps, including confound estimation and surface reconstruction.

    What to Look For

    Verify that the colored overlays align with the visible anatomy. The grey matter overlay should trace the cortical surface, and white matter should remain in the brain interior. Misclassification often occurs at the brain boundary (dura being included) or in deep structures. Poor segmentation may indicate poor T1w image quality.

    ✓ Good Signs
    • Grey matter follows the cortical ribbon
    • White matter fills the interior of the brain
    • CSF fills the ventricles and surrounds the brain
    • No tissue class "leaking" into wrong regions
    ✗ Problems
    • Grey matter labeled as white matter (or vice versa)
    • Skull or dura classified as brain tissue
    • Large holes in the segmentation
    • Segmentation extends outside the brain

    Spatial Normalization

    sub-*_space-MNI152NLin2009cAsym_T1w.svg

    What This Shows

    The subject's T1-weighted brain warped into standard MNI space, overlaid on the MNI template. This verifies that the nonlinear registration successfully aligned the subject's anatomy to the standard template. Good normalization is essential for group-level analyses where all subjects need to be in the same coordinate space.

    What to Look For

    Look at the edges of the brain -the subject's outline should closely follow the MNI template outline. Perfect alignment is not expected (individual brains differ), but the major structures (central sulcus, Sylvian fissure, ventricles) should be roughly aligned. Poor normalization usually stems from poor T1w quality or atypical brain anatomy.

    ✓ Good Signs
    • Brain outlines closely match the template
    • Major sulci and gyri align between subject and template
    • Ventricles are roughly in the correct position
    ✗ Problems
    • Large misalignment (brain shifted or rotated)
    • Severe stretching or distortion of brain structures
    • Template visible beyond subject brain edges

    These figures verify that the functional data was correctly aligned to the anatomy and that noise removal steps identified appropriate regions.

    Coregistration

    sub-*_ses-*_task-*_desc-coreg_bold.svg

    What This Shows

    The mean BOLD image overlaid on the T1-weighted anatomical image, showing how well the functional data was aligned ("coregistered") to the structural scan. The overlay typically alternates between the two images so you can check edge alignment.

    What to Look For

    Focus on the brain boundary and internal structures (ventricles, central sulcus). The BOLD-to-T1w alignment should be tight.     ✓ Good Signs

    sub-*_ses-*_task-*_desc-rois_bold.svg

    What This Shows

    The regions of interest (ROIs) used by CompCor for noise estimation, overlaid on the BOLD image. CompCor extracts noise signals from white matter and CSF -regions where "real" neural signal should be minimal. The colored masks show which voxels were selected for noise estimation.

    What to Look For

    The masks should stay within their respective tissue types. If the WM or CSF mask extends into grey matter, the CompCor confound regressors may inadvertently remove real neural signal from your data. This usually indicates a coregistration or segmentation problem upstream.

    ✓ Good Signs
    • WM mask confined to white matter regions

    CompCor Variance Explained

    sub-*_ses-*_task-*_desc-compcorvar_bold.svg

    What This Shows

    A plot showing the cumulative variance explained by successive CompCor components. The x-axis shows the component number, and the y-axis shows the proportion of variance explained. Separate lines are drawn for anatomical CompCor (aCompCor, based on anatomy) and temporal CompCor (tCompCor, based on temporal variance).

    What to Look For

    Most researchers use the first 5-6 aCompCor components as confound regressors. This plot tells you whether that number captures most of the noise variance. If the curve is still rising steeply at component 6, you might consider including more components. If the first component alone explains almost all variance, investigate what single noise source is dominating (often respiration or a hardware artifact).

    ✓ Good Signs
    • First few components explain most variance
    • Curve plateaus after 5-10 components
    • Both aCompCor and tCompCor curves present
    ✗ Problems
    • First component explains >80% of variance (one dominant noise source)
    • Very flat curve (noise distributed across many components)
    • Missing curves (CompCor estimation may have failed)

    Carpet Plot

    sub-*_ses-*_task-*_desc-carpetplot_bold.svg

    What This Shows

    fMRIPrep's version of the carpet plot, similar to the MRIQC carpet plot but applied to the preprocessed data. It shows the BOLD signal for every voxel (rows) over time (columns), grouped by tissue type. Above the carpet, traces of key confound signals (framewise displacement, DVARS, global signal) are displayed.

    What to Look For

    Compare this to the MRIQC carpet plot -preprocessing should have reduced the prominence of motion artifacts. If strong vertical stripes remain, additional denoising during your statistical analysis (e.g., scrubbing, ICA-AROMA) may be necessary. Pay attention to the confound traces above: spikes in FD > 0.5 mm identify high-motion volumes you may want to censor.

    ✓ Good Signs
    • Smoother texture compared to the MRIQC carpet (preprocessing cleaned up noise)
    • Fewer vertical stripes than the raw data
    • FD and DVARS traces are low and stable
    ✗ Problems
    • Persistent vertical stripes after preprocessing (residual motion)
    • Global signal fluctuations still visible
    • Correlated patterns across all tissue types (non-neural)

    Confound Correlations

    sub-*_ses-*_task-*_desc-confoundcorr_bold.svg

    What This Shows

    A correlation matrix showing the relationships between all estimated confound regressors (motion parameters, CompCor components, physiological signals, etc.). High correlations between confounds indicate redundancy -you don't need to include both if they capture the same noise source.

    What to Look For

    Use this figure when choosing which confound regressors to include in your statistical model. Highly correlated regressors are redundant -including both wastes degrees of freedom. If motion parameters are strongly correlated with CompCor components, this suggests motion contamination in the noise ROIs, which may indicate poor coregistration or severe motion.

    ✓ Good Signs
    • Motion parameters form a correlated block (expected)
    • CompCor components are largely uncorrelated (by design)
    • No single confound correlated with everything
    ✗ Problems
    • Global signal correlated with many confounds (motion-contaminated data)
    • CompCor components highly correlated with motion (mask contaminated)
    • All confounds forming one large correlated block

    🔗 Connectivity Analysis

    Functional connectivity quality check - metrics, thresholds, heatmaps, and output files

    The pipeline uses Nilearn to extract time series from brain regions, apply motion scrubbing, and compute functional connectivity matrices. This page explains how connectivity analysis works, what outputs it produces, and how to read the quality check metrics in the report.

    Note: Connectivity estimates are especially sensitive to head motion. Even small movements can introduce spurious short-range correlations and distort network structure (Power et al., 2012; Satterthwaite et al., 2013). The pipeline applies stricter motion thresholds for connectivity than for general preprocessing. Thresholds and the scrubbing strategy follow recommendations from Wang et al., 2024.

    Connectivity Analysis Quality Check

    The connectivity analysis runs on fMRIPrep-preprocessed BOLD data and proceeds through these steps:

    1. Load confounds - Nilearn’s load_confounds_strategy with the “scrubbing” preset automatically selects nuisance regressors (motion parameters, signal components, their derivatives) and flags high-motion volumes for censoring.
    2. Volume censoring (scrubbing) - Volumes whose framewise displacement (FD) exceeds the threshold are removed from the time series before any connectivity computation. The pipeline uses an FD threshold of 0.2 mm, the most stringent option evaluated by Wang et al. (2024). This aggressive threshold was shown to be the most effective at reducing distance-dependent motion artifacts (DM-FC) across multiple datasets. If scrubbing removes more than 80% of a run’s volumes, the run is flagged as unsuitable - following the same exclusion criterion used in that benchmark.
    3. Time-series extraction - Using the Schaefer 2018 cortical atlas (100 parcels) combined with the Tian subcortical atlas (16 regions) for a total of 116 ROIs, the pipeline extracts the average signal from each brain region. The signal is detrended, z-scored, and bandpass filtered (0.01-0.1 Hz).
    4. Connectivity matrix - Pearson correlation coefficients are computed between all pairs of ROIs, producing a 116 × 116 symmetric matrix. Values range from −1 (perfectly anti-correlated) to +1 (perfectly correlated).

    Why the 0.2 mm Threshold?

    Wang et al. (2024) evaluated four scrubbing variants - liberal (FD > 0.5 mm) and aggressive (FD > 0.2 mm), each with and without Global Signal Regression (GSR). The aggressive 0.2 mm threshold consistently achieved the best denoising performance. It is also the default when calling Nilearn’s load_confounds_strategy(“scrubbing”).

    The trade-off is data loss: stricter thresholds censor more volumes, which can reduce statistical power. For populations with high motion (e.g., pediatric or clinical cohorts), the more liberal 0.5 mm threshold may be preferable as it still reduces motion artifacts effectively while retaining more temporal degrees of freedom. The pipeline’s quality metrics (Censored Volumes, Usable Time, Loss of DoF) help you judge whether the 0.2 mm threshold has removed too much data for a given run.

    Quality Metrics

    The pipeline report includes a per-run quality table for connectivity analysis. The metrics at a glance:

    • Mean FD - average framewise displacement. < 0.25 mm OK, 0.25-0.50 mm caution, > 0.50 mm unsuitable.
    • Censored - percentage of volumes flagged by the scrubbing strategy and removed before time-series extraction. > 80% = not suitable.
    • Usable Time - clean scan duration remaining after censoring (in minutes). < 1 min = not suitable.
    • # Regressors - number of confound columns selected by the scrubbing strategy.
    • Loss of DoF - total temporal degrees of freedom consumed by regressors + censored volumes. High values reduce statistical power. > 60% = caution.

    Connectivity Heatmaps

    The pipeline generates two types of heatmaps for each BOLD run, shown in the report under a collapsible “Show heatmaps” toggle. These visualize the functional connectivity matrix computed from the scrubbed data.

    Full Connectivity Matrix
    Network-Level Summary

    Full Connectivity Matrix

    What This Shows

    A 116 × 116 correlation matrix showing the Pearson correlation between every pair of brain regions. Rows and columns are organized by network (Visual, Somatomotor, Dorsal Attention, Salience/Ventral Attention, Limbic, Frontoparietal Control, Default Mode, and Subcortical). Warm colors (red) indicate positive correlations; cool colors (blue) indicate negative (anti-)correlations. Black lines separate network boundaries.

    What to Look For

    A healthy connectivity matrix shows a clear “checkerboard” pattern: warm squares along the diagonal (regions in the same network are correlated) and a mix of warm and cool off-diagonal blocks (different networks have varying relationships). If the entire matrix is uniformly warm, residual motion is likely inflating correlations - check the Mean FD and censoring metrics. If a single row or column stands out, that ROI may fall in a region of signal dropout.

    ✓ Good Signs
    • Warm blocks along the diagonal (within-network connectivity)
    • Clear block structure following network boundaries
    • Anti-correlations between task-positive and default-mode networks
    ✗ Problems
    • Uniformly warm everywhere (motion artifact inflating correlations)
    • No visible block structure (poor denoising or registration)
    • Single row/column of extreme values (bad ROI)

    Network-Level Summary

    What This Shows

    The full 116-ROI matrix collapsed into an 8 × 8 network-level summary. Each cell shows the mean correlation between all ROI pairs belonging to two networks. Diagonal cells represent average within-network connectivity; off-diagonal cells represent between-network connectivity. Values are annotated on each cell for easy reading.

    What to Look For

    This summary is the quickest way to check whether the connectivity matrix looks biologically plausible. Within-network values should be positive and higher than between-network values. The Default Mode Network typically shows negative correlations with task-positive networks (Dorsal Attention, Frontoparietal Control) during rest - this anti-correlation is a well-established finding and a good sign that denoising was effective.

    ✓ Good Signs
    • Diagonal values higher than off-diagonal (networks are internally coherent)
    • Default Mode shows anti-correlation with Dorsal Attention / Control
    • Sensory networks (Vis, SomMot) cluster together
    ✗ Problems
    • All values near zero (too much data removed or poor signal)
    • All values strongly positive (residual motion artifact)
    • No clear difference between within- and between-network values

    Common issues with Docker, FreeSurfer, data, and fMRIPrep

    This section covers common issues and their solutions. Most problems fall into a few categories: Docker configuration, missing files, or memory limits.

    Docker Issues

    Docker is not running

    Error: Cannot connect to the Docker daemon

    Solution
    1. Open Docker Desktop
    2. Wait for it to fully start (the whale icon should stop animating)
    3. Verify with: docker info
    4. Re-run the pipeline

    Docker out of memory

    Container killed / OOM / Exit code 137

    Solution
    1. Open Docker Desktop → Settings → Resources
    2. Increase RAM to at least 8 GB (16 GB recommended)
    3. Reduce parallel workers: --parallel 2

    Solution

    The pipeline will automatically look for local .tar image files as a fallback. If you have pre-downloaded images:

    1. Save the Docker image: docker save nipreps/fmriprep:latest > fmriprep.tar
    2. Place the .tar file in the working directory
    3. The pipeline will load it automatically

    Alternatively, check your internet connection and Docker Hub status.

    • The input directory should contain subject folders (any naming convention works)
    • Session subfolders are optional and can use common names like MRI1, ses-01, baseline, etc.
    • Verify the path you provided is correct and accessible
    • Make sure folders contain raw DICOM files (.dcm, .ima)

    Missing or truncated scans

    WARNING: Expected X volumes, found Y

    Solution

    This usually means the DICOM export was incomplete:

    • Re-export the affected scan from the scanner console or PACS
    • Check that all DICOM files are present (no partial transfers)
    • If intentionally shortened (e.g., scan was stopped early), note this in researcher comments

    BIDS validation errors

    BIDS quality check: parameter drift / missing required scan

    Solution
    • Parameter drift: Scan parameters (TR, TE, resolution) changed between sessions. This may be intentional (protocol update) or accidental. Document in researcher comments.
    • Missing required scan: A session is missing an expected scan type. Verify the DICOM source data is complete.

    fMRIPrep Failures

    fMRIPrep fails for a specific subject

    fMRIPrep exited with non-zero status

    Solution
    1. Check the execution logs (execution_logs/raw_execution_log.log) for the specific error
    2. Common causes:
      • Poor T1w quality - FreeSurfer can't segment the brain. Check MRIQC structural metrics.
      • Memory limit - Increase Docker memory allocation
      • Disk space - fMRIPrep generates large temporary files. Ensure >20 GB free space.
      • Corrupted NIfTI - Re-run BIDS conversion for this subject
    3. Try re-running just the failed subject

    fMRIPrep is extremely slow

    Processing has been running for >12 hours per subject

    Solution
    • fMRIPrep typically takes 4-8 hours per subject (depending on hardware and number of sessions)
    • If significantly slower:
      • Increase Docker CPU/RAM allocation
      • Reduce parallel workers to avoid resource contention
      • Consider skipping FreeSurfer surface reconstruction (fs_no_reconall) for faster results (loses surface-based outputs)

    Connectivity Quality Check Issues

    Connectivity quality check fails with import error

    ModuleNotFoundError: No module named 'nilearn'

    Solution

    Connectivity quality check requires the nilearn package:

    pip install nilearn

    Or re-install all requirements: pip install -r requirements.txt
